3. **Origin bypass exposure remains:** A desktop-origin direct-connect `curl --noproxy '*' --resolve 'www.ishinaillab.com:443:147.93.78.149'` retrieved production homepage **HTTP 200**, while HTTP on port 80 redirected **301** to HTTPS. WordPress MU guards operate at the origin and remain necessary. Authenticated Origin Pulls or shared-host compatible origin access controls would close this *perimeter* gap but require carefully verified Hostinger/server support and rollback before activation; indiscriminate Cloudflare-IP filtering in `.htaccess` could break requests if Hostinger restores original viewer IP via real-IP modules. **No untested origin restriction was deployed**, avoiding live booking/order outages.
